# Same-process editor export dispatch

`createEditorExportDispatcher` is an optional code-only adapter for the existing owning Node process. Composition remains intent-only unless the owner supplies `editorDispatch`. This change installs no runtime, route, credential, environment switch, scheduler or source-preparation processor. Hosted connection and original-service installation remain separate prerequisites.

Construct the worker with trusted immutable source SHA identities, then pass that same object to `MarketingEditor`, the dispatcher, `preparedEditorMedia` and, when enabled, `editorCancellation`. The dispatcher captures an exact static `EditorBinding`. Its constructor verifies the editor's owner, original project/source allowlist and worker object identity; composition verifies its owner/editor identity and requires the same prepared-media worker. A supplied cancellation port must also be that worker. Source-based child creation never adds a render binding.

Only a fresh successfully recorded public `request_editor_export` calls the dispatcher, before response projection. The dispatcher validates the request/target/receipt and rereads its original immutable receipt. Its internal deterministic UUIDs are separately namespaced for owner/project/source/request claim identity and attempt/outcome identity. Existing locked editor transitions decide whether the claim is current. Only a nonreplayed claim with a complete claimed receipt and matching attempt may prepare; an old saved claim can never rerender.

The adapter awaits `worker.prepare` and asks the editor to commit `prepared`. It discards the preparation return value. The editor independently reads exact-attempt proof from the same worker and retains its existing source, spec, asset, epoch and artifact-hash checks. Preparation has no job attachment, publication, provider or queue handoff.

After a confirmed fresh claim, a failure can best-effort record only `uncertain` for that exact attempt. It never invents `failed_before_dispatch`. An unknown claim response leaves its durable pending/claimed state alone. The editor's CAS prevents fallback from downgrading prepared, canceled, cancel-requested, stale or deleted state. Errors after intent commit report an uncertain HTTP outcome with instructions to retain the original command UUID. The immutable user receipt stays `pending_dispatch`; composition reloads the original snapshot after awaited dispatch to show progress.

Process interruption before the claim leaves pending intent; interruption after it leaves a claimed attempt. Reads, source preparation, save/delete/create/cancel/reconcile and public exact-command replay never dispatch or resume either. Explicit reconciliation and the existing one-to-one supersession rules remain the recovery boundary. There is no second dispatch ledger or automatic retry loop.

The local tests use synthetic records, task-local temporary data and a throwing network stub. `editor-dispatch.test.ts` uses controlled preparation/evidence ports with the original locked store. `composition.test.ts` exercises the public HTTP handlers installed through the synthetic `installMarketingRuntime`, the actual FFmpeg preparation worker, independent outcome proof and protected GET/HEAD/range media. It retains sanitized SHA/size/codec evidence in `.test-artifacts/editor-dispatch/synthetic-public-render.json`. This handler test does not exercise Next middleware, a listener, ingress, real authentication, the original running service or hosted connectivity. Actual-process interruption behavior is covered by the existing separate crash tests; this slice does not change process ownership code or claim a new crash run.
